打底 · 为什么大模型打字慢：大模型一个字一个字往外蹦，每蹦一个新字都要把前文重读一遍。慢的根子不是"算"，是"搬数据"——显卡计算器很快，但数据从内存一趟趟搬过来慢，计算器大半时间在干等。📌 记住：算力是闲的，瓶颈在搬数据。

① 原理 · 投机解码：既然逐字慢，就一次蒙好几个字、再一起检查。比喻——雇个又快又便宜的小秘书（草稿模型）先把后面几个字猜出来，老板（目标模型）一眼扫一整批：对的留下、从第一个错的往后全划掉、自己补一个。为什么快？老板"检查 5 个字"和"检查 1 个字"花的力气几乎一样（瓶颈是搬数据不是算）。而且数学保证结果和老板亲写一模一样 = 无损。

② 原来怎么做 · 两种小秘书各有毛病： - 老办法 A（自回归 / Eagle3）：一个字一个字蒙，连贯但慢，只能蒙短、脑子浅。 - 老办法 B（并行 / DFlash）：一口气全蒙，快、能蒙长，但各蒙各的 → 越往后越前后不搭（"of course" + "no problem" 拼成 "of problem"）。 - → 两难：要么连贯但慢，要么快但后面乱，只能二选一。

③ DSpark 改进了什么 · 两刀治两病： - 改进①半自回归：保留"一口气蒙"的快主力，后面挂个极小的"顺一遍"小助手（Markov head）把前后顺起来。反直觉：一口气蒙的第一个字反而更准（不怕慢 → 脑子能更深），而第一个字最要命（错了后面整串作废）。效果：2 层就超 5 层的老 B、几乎不增时间（+0.2~1.3%）、蒙对长度 +最多 30%。 - 改进②聪明检查：给每个蒙的字打"把握度"，再按忙闲调度——闲时多查、忙时只查最有把握的前几个，把力气省给排队的人。效果：上线 V4 后单用户出字 +60~85%，检查长度从固定 2 个变成按忙闲在 4–6 个之间伸缩。

一句话总账：

怎么做 治什么毛病 有什么效果
投机解码（地基） 秘书先蒙、老板一次批一整批 逐字太慢 无损提速，质量不变
改进①半自回归 一口气蒙 + 小助手顺一遍 一口气蒙后面会乱 2 层 > 5 层、+最多 30%
改进②聪明检查 打把握度 + 看忙闲调度 高并发整串检查浪费 单用户出字 +60~85%

1. 一图读懂：DSpark 在解决什么

【事实】大模型逐字吐字（自回归），延迟正比于输出长度。投机解码标准套路：小草稿模型一次猜 γ 个 token → 大目标模型一次前向并行验证 → 接受最长正确前缀，遇首个错丢弃其后 + 补 1 个 bonus token。拒绝采样保证输出分布与逐字生成严格一致 → 无损。

每 token 接受概率：min(1, p_target(x) / p_draft(x))，从左到右验，首个被拒则其后全弃。

统御全文的延迟公式（论文 Eq.1）：

L = (T_draft + T_verify) / τ
       起草耗时   验证耗时    每轮接受 token 数

【事实】提速 = 动三个杠杆，DSpark 的定位：

杠杆 含义 谁动它
① 降 T_draft 草稿起得更快 并行草稿（一次出整串，已有技术）
② 升 τ 每轮多被接受几个 DSpark 创新一：半自回归（§3）
③ 降有效 T_verify 别验注定被拒的 token DSpark 创新二：置信度调度（§4）

【观点】论文真正的切口在③：过去两年所有投机解码工作都在卷①②（草稿端），没人认真管③。DSpark 第一次把"验证多长"当成一个随负载实时调度、还保证无损的问题——这是它区别于一堆同类论文的根本。

2. 背景：两条草稿老路的死结

【事实】草稿模型的设计决定 T_draft 和 τ 怎么权衡，已有两类：

路线 代表 T_draft τ（接受） 死结
自回归草稿 Eagle3 ∝ γ（线性增长） 高、连贯 为压延迟只能写短块、浅网络（1 层）
并行草稿 DFlash ≈ O(1)（与块长无关） 尾部快速衰减 各位置独立预测 → 多模态碰撞

【事实】多模态碰撞（multi-modal collision）：上下文同时支持 "of course" 和 "no problem"，并行独立预测可能拼出 "of problem" / "no course"——因为每个位置在所有可能前驱上做边缘化，而非条件于实际采样的那一个。

DFlash 是 SOTA 并行草稿：靠从目标模型注入 KV 上下文特征（KV injection），块内双向注意力，共享目标模型冻结的 embedding + LM head，一次前向出全部 γ 个 logits → 能用更深网络、更大块。但并行本质决定越往后越前后不一致。

3. 创新一：半自回归生成（升 τ，不牺牲 T_draft）

3.1 结构：并行骨干 + 轻量串行

【事实】重活由并行骨干（就用 DFlash）一次前向干完，产出隐藏态 h₁…h_γ 和基础 logits U₁…U_γ；后接一个轻量串行模块，给每个位置补"前一个 token"的转移偏置 B_k，诱导一个因果块分布：

p_k(v | x_0, x_<k) = softmax( U_k(v) + B_k(x_0, x_<k, v) )

串行模块必须极轻（T_sequential ≪ T_parallel），整体起草延迟仍由并行阶段主导。

3.2 两种串行头（Markov 默认 / RNN 备选）

【事实】Markov head（默认）：只看紧邻前一个 token，本是 V×V 转移矩阵，用低秩分解 B = W₁W₂（W₁∈R^{V×r}, W₂∈R^{r×V}, r=256）压到极小：

B(x_{k-1}, ·) = W₁[x_{k-1}] · W₂   ∈ R^V

W₁ 当 embedding 查表、W₂ 当 logit 投影。大词表下存储和单步计算都很小。白话：一旦位置 1 采到 "of"，Markov head 在位置 2 抬高 "course"、压低 "problem"。

【事实】RNN head（备选）：维护跨整块的循环状态 s_k，记忆超过一步。实测只在长草稿上比 Markov 略好，但实现复杂、部署不划算 → 默认仍用 Markov head。

3.3 反直觉发现：并行为什么赢自回归（§4.3.1）

【事实】主表显示并行(DFlash)和半自回归(DSpark)常比纯自回归(Eagle3)接受更长——与"逐字更连贯更准"的直觉相反。论文用逐位置条件接受率（剔除前缀被拒的惩罚，单看每个位置本身的预测质量，Qwen3-4B）拆出两层原因：

  • 首位看容量：并行起草与长度无关 → 网络能更深；自回归为控 O(γ) 延迟只能浅。故第一个 token 上 DFlash 0.88 > Eagle3 0.81（数学）、0.72 > 0.53（对话）。
  • 首位权重最高：前缀验证里第一个 token 一被拒，后面整串作废 → 起点杠杆最大，首位优势被不成比例放大。
  • 尾部看依赖：位置 2→7，DFlash 衰减（代码 0.87→0.78、对话 0.72→0.63），Eagle3 反而能稳/升（对话 0.53→0.74）。

【事实】DSpark = 深并行骨干拿高起点（数学首位 0.93）+ Markov head 补尾部衰减 → 全程条件接受率又高又稳。

4. 创新二：置信度调度验证（降有效 T_verify · 论文真正新角度）

【事实】草稿能写很长 ≠ 该整串都验。高并发下多验一个大概率被拒的 token，就占了目标模型本可服务别人的批量算力。瓶颈两因素：① 数据侧——代码等结构化任务接受率天然高于开放对话；② 系统侧——闲时多验近乎免费、忙时是明显浪费。三步走：

4.1 置信度头

【事实】给每个草稿位置输出标量 cₖ∈(0,1)，预测条件存活概率（前面都被接受的前提下，本位 token 能过验证的概率）：

c_k = σ( w^T · [ h_k ; W₁[x_{k-1}] ] )

监督信号 = 草稿与目标分布的总变差距离（TV distance 直接等于接受率）：c*_k = 1 − ½·‖p_draft − p_target‖₁。

4.2 STS 事后校准（为什么必须）

【事实】神经网络置信度系统性偏乐观。关键洞察——调度需要的不是"谁更有把握"的排序，而是存活概率的绝对值（要拿累积乘积 ∏cᵢ 算"该验多长"）。STS（Sequential Temperature Scaling）从左到右逐位做温度缩放，把累积乘积拉回真实接受率，且保序（不打乱原排序）。

【事实】校准效果（Alpaca，Figure 6，ECE 校准前→后 / AUC）：

位置 ECE 前→后 ROC-AUC
Pos 1 5.7% → 2.0% 0.818
Pos 3 8.2% → 1.7% 0.812
Pos 5 5.8% → 0.8% 0.864
Pos 7 3.3% → 0.4% 0.907

原始模型判别力强（AUC 0.81–0.90）但过度自信（ECE 3–8%）→ STS 后平均 ECE 降到 ~1%。

4.3 硬件感知前缀调度器（Algorithm 1）

【事实】把"每请求验多长"建模成全局吞吐最大化：

目标 Θ = τ · SPS(B)
  τ   = 这一批期望接受的 token 总数
  B   = 这一批送进目标模型的 token 总数 = Σ(1 + ℓ_r)
  SPS(B) = 引擎在批大小 B 下每秒步数（初始化时一次性测出成本表，之后 O(1) 查表）
  • 存活概率 a_{r,j} = ∏_{i≤j} c_{r,i} 随位置单调不增 → 贪心按全局存活概率降序逐个纳入即最优。
  • 无损保证靠"提前停止"：吞吐一旦不再升就 break，使纳入决策只依赖到当前步为止的信息，不偷看未来 token（违反"非预期性"的反例见论文 Appendix A）。

【观点】这一步是全文最硬的创新：第一次把投机解码的验证长度做成随系统负载伸缩、且数学无损的调度问题。MTP-1 做不到——它要么固定验 2 个，要么 MTP-3/5 固定验更多（高并发反而拖垮吞吐），没法随负载伸缩。

5. 训练（一节带过）

【事实】目标模型全程冻结；草稿模型共享并冻结其 embedding + LM head，只训骨干/串行块/置信度头。三 loss 加权（默认 αce=0.1, αtv=0.9, αconf=1.0）：

L = 0.1·L_ce(交叉熵) + 0.9·L_tv(分布匹配,最小化TV距离=最大化接受率) + 1.0·L_conf(置信度BCE)

各位置按 w_k = exp(−(k−1)/γ) 加权——靠前位置权重更高（呼应"首位杠杆最大"）。数据：Open-PerfectBlend 1.3M（对话17.6%/数学39.4%/代码38.9%/指令4.1%），只用 prompt、response 由各目标模型重新生成，训 10 epoch。离线对比：Eagle3=1 层，DSpark/DFlash=5 层，块长 7。

7. 生产部署：DeepSeek 系统能力的半壁江山

【事实】生产配置：γ=5，并行骨干=3 个 MoE 层 + mHC + 滑窗 128，Markov head，置信度头端到端联训后 STS 校准。

7.1 可扩展训练（HAI-LLM 框架）

  • 隐藏态通信：只传 LM head 前的隐藏态而非全词表 logits，通信复杂度 O(V≈10⁵) → O(d)。
  • 锚点定界序列打包：采样固定数量草稿锚点打成密集 batch，用 token 级注意力索引而非 2D mask，把草稿计算从目标上下文长度解耦。

7.2 调度器落地的两个冲突 + 解法

【事实】真实 SPS(B) 不是平滑曲线而是锯齿状跳变；动态 token 数和 CUDA graph / 零开销调度 ZOS 打架。解法=异步化：用"两步前"的置信度预估本步该验多长（变成动态 top-K），当前 token 实际排序仍用最新累积置信度。"两步前"天然形成因果屏障——既能去掉提前停止做无约束全局搜索（绕锯齿陷阱），又不泄露未来 token，保住无损。

7.3 变长 kernel + 与 V4 稀疏注意力协同

【事实】变长验证需 kernel 支持：把所有请求的 token 拍平当独立元素处理，块内依赖靠 marker tensor 传入稀疏注意力实现。在 V4 架构上只需改 index-attention 和 compress 两个 kernel。

【观点】这是 DSpark 与 V4 的 CSA/HCA 稀疏注意力同源协同设计的直接证据——印证 DeepSeek "算法-系统-硬件"一体化打法。

7.4 线上实测（vs MTP-1，Figure 7/8）

【事实】+661%/+406% 论文自注="把可用交互档位往外扩，不是真倍数提速"。负载自适应：验证预算从 MTP-1 静态 2 token → 中等负载 4–6 token，高并发自动收紧（闲时多验、忙时留批量给排队请求）。

7.5 短板（论文自陈）

【事实】起草第一块草稿是固定开销，遇本身难、接受率低的请求收不回。后续方向=草稿模型按难度提前停（difficulty-aware early exit）。

8. 精读判断（观点）

  1. 真正的新意在"验证"不在"草稿"。半自回归是把 DFlash + Eagle3 的优点缝起来（高质量工程整合）；算硬创新的是把验证长度做成随负载实时调度、还严格无损的问题——业界第一次系统性做并落主力产品。
  2. "无损"是贯穿始终的纪律。拒绝采样 → 提前停止 → 异步因果屏障，每一步都小心不破坏"输出分布严格等于目标模型"。这是它敢直接换掉线上 MTP-1 的底气。
  3. 护城河在工程不在算法。算法已开源可复现（DeepSpec）；真正难抄的是"在 V4 生产系统跑通"那一摊——HAI-LLM 训练优化、ZOS 异步调度、变长 kernel、SPS 成本表、与稀疏注意力协同。这部分别家短期难复制。
  4. 协同设计的味道很重。只改 2 个 kernel 就上 V4，说明 DSpark 和 V4 稀疏注意力是一套人马协同设计。

9. 投资 read-through（简短）

【观点】放回 token 经济方程 紧缺度 = g_D − (g_S + g_E)，DSpark 是 g_E（每 FLOP 产 token 效率）的一个增量——与稀疏注意力正交、可叠加的"第二把降本刀"（稀疏=少读 KV，投机=打断逐字串行）。对格局的意义不在技术本身，而在继续强化"中国大模型在受限算力下用算法/系统工程对冲硬件代差"主线：同一批 GPU 单用户出字 +60–85%，直接改写 MaaS 单位经济（每 token 成本、每卡服务用户数）。不下评级；值得跟的观察锚：① V4 线上 token 单价是否随之下调（验 g_E 是否传导到价格）② 昇腾推理集群规模化进度 ③ GLM/MiniMax/Kimi 是否跟进投机解码（目前只有 DeepSeek 在主力产品落地）。
